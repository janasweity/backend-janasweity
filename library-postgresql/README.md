# Library PostgreSQL Project

مشروع قاعدة بيانات لإدارة كتب المكتبة وإعاراتها. كل كتاب مرتبط بمؤلف، وكل إعارة مرتبطة بكتاب. استخدمت مفاتيح أساسية وأجنبية، وقيدًا يمنع أن يكون تاريخ الإرجاع قبل تاريخ الإعارة.

## طريقة التشغيل

أنشئي قاعدة بيانات فارغة باسم `library_db` في pgAdmin، وافتحي Query Tool وشغّلي الملفات بالترتيب:

1. `01-schema.sql` — إنشاء جداول المؤلفين والكتب والإعارات.
2. `02-seed.sql` — إضافة بيانات تجريبية.
3. `03-queries.sql` — تجربة الإضافة والقراءة والتعديل والحذف، و`JOIN` و`GROUP BY` وتقسيم النتائج إلى صفحات.
4. `04-transactions.sql` — تجربة تثبيت الإضافة بـ `COMMIT` والتراجع عن التعديل بـ `ROLLBACK`.
5. `05-index.sql` — شغّلي الأوامر الثلاثة واحدًا واحدًا لمقارنة خطة التنفيذ قبل إنشاء الفهرس وبعده.

## نتائج التحقق

ظهر اسم المؤلف بجانب كل كتاب في `JOIN`، وأظهر `GROUP BY` كتابين لتولكين وكتابًا واحدًا لفرانك هربرت. ظهرت أول نتيجتين في الصفحة الأولى، وظهر كتاب Dune في الصفحة الثانية. ثبّت `COMMIT` إضافة الكتاب التجريبي، وأبقى `ROLLBACK` تصنيفه الأصلي `Fantasy`.

## تقييم الفهرس

استخدمت `EXPLAIN ANALYZE` للبحث عن Dune قبل إنشاء فهرس `books_title_idx` وبعده. ظهرت خطة `Seq Scan on books` في الحالتين. كان زمن التنفيذ `0.106 ms` قبل الفهرس و`0.099 ms` بعده. الفرق الصغير لا يثبت تحسن الأداء، لأن PostgreSQL قرأ الجدول مباشرة في المرتين.

## استخدام AI

استخدمت ChatGPT للمساعدة في تصميم الجداول وكتابة بيانات تجريبية واستعلامات SQL. شغّلت الاستعلامات بنفسي في pgAdmin، وتحققت من النتائج، وقارنت خطة التنفيذ قبل الفهرس وبعده.
